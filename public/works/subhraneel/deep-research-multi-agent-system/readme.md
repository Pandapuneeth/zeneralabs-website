# Deep Research Multi-Agent System
A multi-agent deep research system built with LangGraph that autonomously transforms complex research questions into structured, evidence-backed reports. It decomposes questions into research tasks, searches and fetches sources using Exa and Firecrawl, scores and organizes evidence by quality, analyzes each sub-question, and uses a critique agent to identify unsupported claims, missing evidence, contradictions, and research gaps. When necessary, the system performs follow-up research before synthesizing a final report with citation and claim-level traceability. It also provides real-time research progress through SSE and a Next.js frontend.

## Agents

The system runs a chain of nodes to turn a user's research question
into concrete, researched answers backed by cited sources.

1. **understand_research_intent** (`agent-server/nodes.py`)
   Extracts `target_url` and `entity_name` (if a URL is provided), plus
   `objective`, `domain`, `scope`, `constraints`, and `expected_output`
   from the user's question. URLs are detected via LLM reasoning with a
   regex fallback.

2. **planning_agent** (`agent-server/nodes.py`)
   Decomposes the research objective into specific, researchable
   sub-questions and defines the `research_strategy`.

3. **generate_research_tasks** (`agent-server/nodes.py`)
   Turns the sub-questions into concrete research tasks (each with a targeted
   `search_query` the search layer can execute).

4. **search_and_fetch** (`agent-server/nodes.py`)
   For each research task: runs Exa search to find relevant URLs, then
   fetches the top results with Firecrawl to get full page content. If a
   `target_url` was provided, also fetches it directly as primary evidence.
   Stores everything as evidence via the `EvidenceStore`.

5. **analyst_agent** (`agent-server/nodes.py`)
   Answers each sub-question using the collected evidence. For every
   sub-question, it gathers the top-N evidence items by quality score,
   passes them to the LLM, and produces an answer with inline citations.
   Results are stored in `analysis_results`.

6. **critique_agent** (`agent-server/nodes.py`)
   Reviews all analysis results in a single LLM call, checking for
   unsupported claims, missing evidence, weak sources, contradictions,
   and research gaps. Generates follow-up search queries (actual searchable
   queries, not gap descriptions). If research is insufficient and loops
   remain, routes to follow-up search. If sufficient (or max loops reached),
   routes to synthesis.

7. **follow_up_search** (`agent-server/nodes.py`)
   Processes only the follow-up tasks generated by the critique agent.
   Runs Exa search + Firecrawl fetch on each, **appends** new results to
   existing `search_results` and `evidence_items` (without overwriting), then
   routes back to the analyst for re-evaluation.

8. **synthesis_agent** (`agent-server/nodes.py`)
   The final step. Produces a structured research report from the
   collected evidence and analysis. Every claim is traceable to specific
   evidence IDs and source URLs. Includes an executive summary, findings
   per sub-question, limitations, references, and confidence scores.

## Graph

The workflow is defined in `agent-server/graph.py` and moves the shared
`ResearchState` (`agent-server/state.py`) through:

```
START
  -> understand_research_intent
  -> planning_agent
  -> generate_research_tasks
  -> search_and_fetch
  -> analyst_agent
  -> critique_agent --(sufficient or max loops)--> synthesis_agent -> END
        |
        v (insufficient + loop < max)
    follow_up_search -> analyst_agent -> critique_agent -> ...
```

The LLM agents call `gpt-4o-mini` via litellm using a structured
`response_format` from `agent-server/schemas/output_types.py` (Pydantic models
that the LLM must return as JSON). Nodes update the state with a
`Command(update=..., goto=...)` and retry themselves on parse errors. The graph
nodes are registered with a `RetryPolicy` of 3 attempts.

`search_and_fetch` uses Exa for web search and Firecrawl for page fetching.
API keys are read from the environment (`EXA_API_KEY`, `FIRECRAWL_API_KEY`).

## Evidence Store

Raw `search_results` and `fetched_sources` are unstructured lists. The
**EvidenceStore** (`agent-server/evidence_store.py`) extracts, normalises, and
deduplicates them into a queryable collection of `EvidenceItem` objects stored
in `ResearchState.evidence_items`.

Each `EvidenceItem` retains:

| Field | Description |
|---|---|
| `evidence_id` | Deterministic hash of `source_url + task_id` |
| `research_task_id` | The research task this evidence supports |
| `source_url` | Canonical URL of the source |
| `source_title` | Title of the page/document |
| `source_domain` | Extracted domain (e.g. `arxiv.org`) |
| `source_metadata` | Author, published date, search query, status code, etc. |
| `excerpt` | The exact passage extracted from the source |
| `source_type` | `search_result` or `fetched_source` |
| `quality_score` | Composite quality score (0.0 - 1.0) |

The `EvidenceStore` is instantiated inside each tool node and its output
(serialised list of `EvidenceItem`) is merged into the graph state via the
`Command(update=...)` mechanism.

### Query methods

```python
store.query_by_task(task_id)                                    # all evidence for a task
store.query_by_url(url)                                         # all evidence from a URL
store.query_by_domain(domain)                                   # all evidence from a domain
store.query_by_quality(desc=True)                               # all evidence sorted by score
store.query_by_sub_question(question, tasks, n=5)               # top N evidence for a sub-question
store.get_top_sources(n=5)                                      # top N highest-scored items
store.get_top_by_task(task_id, n=3)                             # top N per task
store.get_task_coverage()                                       # task_id -> item count
store.get_unique_sources()                                      # deduplicated URL list
```

## Source Quality Scoring

Every evidence item is scored on ingest by `agent-server/source_scoring.py`
using a weighted composite of four metadata signals:

| Component | Weight | Source | Score logic |
|---|---|---|---|
| **Relevance** | 35% | Exa `result.score` | Direct 0-1 from API; fetched sources get neutral 0.5 |
| **Freshness** | 25% | Exa `published_date` / Firecrawl metadata | Exponential decay with 365-day half-life; unknown = 0.5 |
| **Author presence** | 20% | Exa `author` / Firecrawl `metadata.author` | Has author = 1.0, missing = 0.3 |
| **Content quality** | 20% | Excerpt length | <100 chars = low, 100-2000 = linear scale, 2000+ = max |

```
quality_score = (relevance * 0.35) + (freshness * 0.25)
              + (author * 0.20)   + (content * 0.20)
```

Scores are computed automatically when `EvidenceStore.ingest_search_result()`
or `EvidenceStore.ingest_fetched_source()` is called. The metadata used for
scoring is captured from Exa and Firecrawl in `nodes.py`:

- **Exa**: `result.score`, `result.published_date`, `result.author`
- **Firecrawl**: `metadata.author`, `metadata.description`, `metadata.statusCode`

## Analyst Agent

After evidence collection, the **analyst_agent** (`agent-server/nodes.py`)
answers each sub-question using the gathered evidence.

### How it works

1. Rebuilds an `EvidenceStore` from the serialised `evidence_items` in state.
2. For each sub-question, calls `query_by_sub_question()` to find all research
   tasks targeting it, then returns the top-5 evidence items by quality score.
3. Formats the evidence excerpts into a structured prompt and calls the LLM.
4. Parses the LLM response into an `AnalysisResult` containing the answer,
   inline citations, and evidence count.

### Output model

Each sub-question produces an `AnalysisResult` (`agent-server/state.py`):

```python
class Citation(BaseModel):
    source_url: str
    source_title: str = ""

class AnalysisResult(BaseModel):
    sub_question: str       # The original sub-question
    answer: str             # Answer with inline [url] citations
    citations: list[Citation]  # All sources referenced
    evidence_count: int     # Number of evidence items used
```

Results are stored in `ResearchState.analysis_results`.

### Prompt

The analyst prompt (`agent_server/agent_prompts.py`) instructs the LLM to:
- Answer using **only** the provided evidence excerpts
- Include inline citations as `[source_url]` markers
- Return `citation_urls` for all referenced sources
- State "insufficient evidence" when excerpts are inadequate

## Critique Agent

After the analyst produces answers, the **critique_agent** (`agent-server/nodes.py`)
reviews all results in a single LLM call and decides whether the research is
sufficient or needs additional investigation.

### What it checks

| Category | Description |
|---|---|
| **Unsupported claims** | Statements in answers not backed by cited evidence |
| **Missing evidence** | Key information that should be present but isn't |
| **Weak sources** | Answers relying on low-quality sources |
| **Contradictions** | Facts that conflict across different sub-question answers |
| **Research gaps** | Important aspects of the objective not covered by any answer |

### Research loop

If the critique finds insufficient research **and** the loop counter is below
the max (1 re-search iteration):

1. The critique agent generates follow-up search queries (actual 2-8 word
   searchable queries, not gap descriptions) from `research_gaps` and
   `missing_evidence` findings.
2. Routes to **follow_up_search**, which processes only the new tasks via Exa
   + Firecrawl and **appends** results to existing `evidence_items` (no data lost).
3. Routes back to **analyst_agent**, which re-answers all sub-questions with
   the accumulated evidence.
4. The **critique_agent** runs again. Since `loop_count >= 1`, it forces
   `research_sufficient = True` and routes to synthesis.

If the critique finds research sufficient on the first pass, it routes
directly to synthesis.

### Output model

```python
class SubQuestionReview(BaseModel):
    sub_question: str
    unsupported_claims: list[str] = []
    missing_evidence: list[str] = []
    weak_sources: list[str] = []
    notes: str = ""

class CritiqueResult(BaseModel):
    reviews: list[SubQuestionReview] = []
    contradictions: list[str] = []
    research_gaps: list[str] = []
    follow_up_search_queries: list[str] = []  # Actual search engine queries
    research_sufficient: bool = False
```

Results are stored in `ResearchState.critique_results`. The loop state is
tracked via `research_loop_count`, `research_sufficient`, and `follow_up_tasks`.

## Synthesis Agent

After the critique agent confirms research is sufficient, the **synthesis_agent**
(`agent-server/nodes.py`) produces the final structured research report. This is
the last node in the graph before `END`.

### How it works

1. Builds full context: the research objective, all analysis answers, the
   complete evidence store (with `evidence_ids`), and the critique findings.
2. Calls the LLM with a prompt that instructs it to extract claims **only**
   from the provided evidence and reference specific `evidence_ids`.
3. Post-processes the LLM output to validate that every `evidence_id` exists
   in the store (invalid ones are stripped).
4. Builds `Reference` objects from cited source URLs, linking each source to
   all its `evidence_ids` and quality score.
5. Assembles the final `SynthesisResult` and stores it in state.

### Output model

```python
class ResearchClaim(BaseModel):
    claim: str                          # Single factual claim
    evidence_ids: list[str]             # Evidence IDs supporting this claim
    source_urls: list[str]              # Source URLs for traceability
    confidence: float                   # 0.0 - 1.0 per claim

class Reference(BaseModel):
    source_url: str
    source_title: str = ""
    source_domain: str = ""
    evidence_ids: list[str] = []        # All evidence from this source
    quality_score: float = 0.0

class FindingSection(BaseModel):
    sub_question: str
    summary: str
    claims: list[ResearchClaim]         # Evidence-backed claims
    confidence: float

class SynthesisResult(BaseModel):
    title: str
    executive_summary: str
    findings: list[FindingSection]      # Per sub-question
    limitations: list[str]              # Gaps, weak areas
    references: list[Reference]         # Full source metadata
    overall_confidence: float
```

### Traceability

Every claim in the report is linked back to specific evidence:
- `ResearchClaim.evidence_ids` references exact `EvidenceItem.evidence_id` values
- `Reference.evidence_ids` groups all evidence from a single source
- Invalid `evidence_ids` are stripped during post-processing
- Source URLs, titles, and quality scores are preserved in `Reference`

### Export

The `SynthesisResult` is fully serializable via Pydantic:

```python
# To dict/JSON
result.model_dump()

# To markdown
result.model_dump_json(indent=2)
```

This can be extended to export to PDF or DOCX by adding a formatter function.

## Chat API

`agent-server/server.py` exposes the full pipeline via two endpoints:

### POST /chat (synchronous)

Returns the complete research trace after the pipeline finishes.

```
POST /chat
{
  "user_input": "your research question"
}
```

### POST /chat/stream (SSE)

Streams research progress in real-time via Server-Sent Events. Each event
carries a partial `ChatResponse` with accumulated state up to that point.

```
POST /chat/stream
{
  "user_input": "your research question"
}
```

Events emitted:

| Event | Description |
|---|---|
| `intent` | Research intent extracted (objective, domain, scope, target_url, entity_name) |
| `planning` | Sub-questions and research strategy defined |
| `tasks` | Concrete research tasks generated |
| `search` | Evidence collected via Exa + Firecrawl |
| `analysis` | Sub-questions answered with citations |
| `critique` | Quality review completed |
| `follow_up_search` | Additional evidence collected (if research was insufficient) |
| `synthesis` | Final report generated |
| `done` | Pipeline complete |
| `error` | An error occurred |

Uses FastAPI's built-in `EventSourceResponse` with automatic keepalive pings.
The frontend uses `@microsoft/fetch-event-source` for reliable SSE parsing
over POST.

### Request

| Field | Type | Required | Description |
|---|---|---|---|
| `user_input` | `str` | Yes | The research question (can include a URL) |

### Response

The full research trace is returned — every stage from intent extraction
through synthesis is serialised and included in the response.

| Field | Type | Description |
|---|---|---|
| `sub_questions` | `list[dict]` | Decomposed sub-questions |
| `research_strategy` | `str` | The research strategy |
| `research_tasks` | `list[dict]` | Concrete research tasks with search queries |
| `fetched_sources` | `list[dict]` | Scraped page content from Firecrawl |
| `search_results` | `list[dict]` | Raw Exa search results |
| `evidence_items` | `list[dict]` | Quality-scored evidence with `evidence_id` |
| `analysis_results` | `list[dict]` | Per-sub-question answers with citations |
| `critique_results` | `list[dict]` | Quality review with research sufficiency verdict |
| `synthesis_result` | `dict` | Final structured report with traceable claims and references |
| `target_url` | `str \| null` | URL extracted from user input (if any) |
| `entity_name` | `str \| null` | Entity name extracted from URL (if any) |
| `objective` | `str` | Extracted research objective |
| `domain` | `str` | Research domain |
| `scope` | `str` | Research scope |
| `constraints` | `list[str]` | Research constraints |
| `expected_output` | `str` | Expected output format |
| `errors` | `list[str]` | Any errors encountered during the pipeline |

### Traceability

The response enables full end-to-end traceability:

1. `sub_questions` → each question has a `research_tasks` entry
2. `research_tasks` → each task produces `evidence_items` via `evidence_id`
3. `evidence_items` → each item has a `quality_score` and `source_url`
4. `analysis_results` → answers reference evidence via `citations`
5. `critique_results` → validates quality across all answers
6. `synthesis_result` → final report links claims to `evidence_ids` and `source_urls`

Start the server with:

```
cd agent-server
uv run uvicorn server:app --reload
```

## Frontend

A Next.js frontend (`web/`) provides a real-time UI for the research pipeline.

```
cd web
npm install
npm run dev
```

Features:
- Real-time SSE streaming showing pipeline progress
- Tabbed view: Report, Intent, Planning, Tasks, Sources, Evidence, Analysis, Critique
- Pipeline progress indicator with stage-by-stage updates
- Auto-merges partial responses as events arrive

## Testing

The test suite uses **pytest** with mocked LLM calls and API clients. All
70 tests run in ~5s with no real API calls.

```
cd agent-server
uv run pytest tests/ -v
```

### Test structure

```
agent-server/
├── conftest.py                   # Shared fixtures, state factories, mock helpers
└── tests/
    ├── test_understand_intent.py   # 6 tests  — intent extraction node
    ├── test_planning_agent.py      # 4 tests  — sub-question decomposition
    ├── test_generate_tasks.py      # 4 tests  — research task generation
    ├── test_search_and_fetch.py    # 5 tests  — Exa search + Firecrawl fetch
    ├── test_analyst_agent.py       # 5 tests  — per-sub-question analysis
    ├── test_critique_agent.py      # 6 tests  — quality review + routing
    ├── test_follow_up_search.py    # 3 tests  — incremental evidence append
    ├── test_synthesis_agent.py     # 4 tests  — final report generation
    ├── test_evidence_store.py      # 14 tests — ingest, query, dedup, indexing
    ├── test_source_scoring.py      # 15 tests — scoring components + composite
    └── test_chat_endpoint.py       # 4 tests  — async integration tests
```

### What's tested

| Layer | What | Mock |
|---|---|---|
| **Unit** (per node) | Each node function in isolation | `litellm.completion`, `Exa`, `FirecrawlApp` |
| **Unit** (store) | EvidenceStore query, dedup, indexing | None (pure logic) |
| **Unit** (scoring) | Quality score components | None (pure math) |
| **Integration** | Full `POST /chat` pipeline end-to-end | LLM + Exa + Firecrawl |

### Adding new tests

Tests import shared factories from `conftest.py`:

```python
from conftest import make_state, make_evidence_item, mock_llm_response

@patch("nodes.completion")
def test_my_node(mock_completion):
    mock_completion.return_value = mock_llm_response({"key": "value"})
    state = make_state(user_input="test question")
    result = my_node(state)
    assert result.goto == "next_node"
```
